# 风神录 3.1：共用平台、保留作品规则

本轮继续沿用 3.0 的 eagler-touhou Launcher、运行时协议与原生 SDL3 平台。没有增加联机、thprac、高刷新率插值等功能；TH10 的关卡、弹幕、自机、计分、录像、原版数值精度仍由原有游戏系统负责。

## 变化

- `portable/input/TouchController.hpp` 由两款游戏实际共用，管理菜单点击/滑动、双指返回、拖动、摇杆、低速与符卡。两款游戏分别提供自己的移动速度、边界和场景状态。
- 渲染热路径改为带类型的 C++ 接口；动画与游戏更新回调直接绑定 C++ 函数。原有资源编号、状态语义与用于兼容的回退仍保留。
- DAT 解压结果使用 32 MiB 上限的 LRU 缓存。每次交给游戏的资源仍是独立可写副本。
- 过关资源创建按原有顺序分步执行，每次约 2 ms 后让出浏览器帧。加载屏障完成前不推进游戏、随机数或录像。单个资源创建仍可能超过预算。
- 两款游戏共用整数截断的精确快速路径；不适用的数值继续由 SoftFloat 处理。

## 验证与边界

加载顺序与原版函数对照覆盖 268 组场景、失败和重试组合；14,000 tick 汉化游戏回归进入二面。共享数值快速路径与 SoftFloat 进行 1,000,000 组随机对照。浏览器测试覆盖触摸、Music Room、存档迁移与离线重开。

这表示平台职责和通用实现进一步统一，并不表示 TH06/07/08/10 的游戏内部源码可以相同。原始精度、作品数据布局和脚本格式继续保留。桌面手机尺寸/CPU 降速测试不等于实体手机验证，也不能保证所有设备没有掉帧。

构建与资源恢复沿用 `ARCHITECTURE-3.0.md`。回归脚本需要开发工作区中的原版对照资产或历史版本；发行包的源码与站点资源可用于重新构建，不包含全部历史测试夹具。
