# 风神录 3.3：对齐 TH06/TH07 的游戏与平台分层

本次核对的是 eagler 项目的 C++ 红魔乡、妖妖梦，而不是工作区另一个 TypeScript 版 `th07_web_ref`。参考版本分别为 TH06 `645bd6a437b58f30f650716eb42a308e85756c02` 和 TH07 `5f80a0df8a8434afd2544d4aaa95691ea4d65f89`；本地源码在 `th10_web/reference/eagler-th06`、`eagler-th07`。没有参考其 TH10 实现。

## 实际相同与不同之处

| 方面 | 参考红魔乡、妖妖梦 | 目前风神录、永夜抄 |
| --- | --- | --- |
| 游戏组织 | 各自的管理器、生命周期和 Chain 原生函数回调；两个游戏的类与布局不完全相同 | 保留各自 Application、场景和游戏管理器；原生更新链直接调用绑定的 C++ 函数。TH10 的其他具名回调改用固定函数表 |
| 渲染 | TH06 接口叫 `GfxInterface`，TH07 叫 `ZunGraphics`；都封装图形后端，仍有固定功能图形概念 | 两款都有显式 `ZunGraphics` 平台接口，并共用具名的深度、雾、混合、颜色及纹理参数命令；SDL/GLES 后端仍负责原版状态语义 |
| 数值 | 游戏源码主要使用 float、double 和普通 C++ 运算 | 基础运算与已验证的整数缩放使用普通 C++ 快速路径；特殊精度、复杂表达式和边界值仍保留 Extended/SoftFloat |
| 加载 | 提前加载菜单 ANM/图片，保留静态纹理；并非所有关卡加载都异步 | 菜单 ANM 已解析、解码并预传静态纹理；空白文字/截图纹理独立分配，复用前恢复初始内容。已有分步加载仍负责游戏场景 |
| 平台与输入 | C++ 平台代码、SDL3、网页 Launcher 和触摸输入 | 同样分层；TH08/TH10 共用 SDL3 平台组件、触控策略和网页协议，游戏状态与移动规则由各自代码提供 |

因此，这是对齐共同的架构方式，不是把四款游戏变成同一份源码。保留原版资源结构、录像格式及用于验证的地址注释；发布运行不因此变回 x86 模拟器。按用户要求，没有加入联机、练习扩展或高刷新率插值，游戏逻辑仍为原版 60 Hz。

## 3.3 的具体改动

`Callbacks.hpp/.cpp` 在原生构建用按具名枚举索引的固定函数表，代替剩余的关联容器查找；更新链已绑定的函数继续直接调用。比较原版用的旧分发接口保留在独立编译分支。

`portable/sdl/RenderCommands.hpp` 提供 `SetDepthFunc`、`SetDepthMask`、`SetFogRange`、`SetColorOp`、`SetTextureArg` 等命令。动画网格、图层、屏幕效果、投影和背景绘制通过语义明确的方法设置图形状态，数值映射集中在边界适配器。它没有删除后端对原版混合、深度、纹理格式的支持，也没有改变这些操作的先后顺序。

`TransitionResources.cpp` 除保存原始模板，还保留 `title.anm`、`title_v.anm` 的静态纹理并提前上传 GPU。空闲缓存纹理可以再次借用；如果存在其他活动所有者则分配独立纹理，内容发生过改写时恢复模板。名称以 `@` 开头的文字和截图纹理始终独立。TH10 的 Music Room 与结果菜单共用标题资源，不套用 TH07 的资源文件名。

初始模板预算仍为 16 MiB（当前约 12.72 MiB），静态驻留纹理另占 CPU 像素与 GPU 存储；16 MiB 不是进程总内存上限。缓存仅覆盖固定的菜单资源，不随游玩关卡无限增长。这是用有限的常驻内存减少重复分配与上传的取舍。

共享 `ScalarMath` 增加整数乘法、乘后取整以及加减整数缩放快速路径，用于人物移动和 TH08 慢速计时。超出精确整数范围、非正常浮点值或特殊舍入时，整个表达式回退到原有计算。没有启用 fast-math，也没有把全部 Extended 强行替换为 float。

## 验证与范围

数值检查覆盖 600,000 组输入、3 种精度和 4 种舍入模式，共 20,400,000 次独立 SoftFloat 对照。两款各进行三次 Music Room 进入/返回，画布与上一稳定版逐像素一致；驻留纹理计数证明实际复用。风神录另验证 14,000 tick 从一面到二面的状态。

当前测试的纹理上传量：TH10 第一次进入 Music Room 从 10,747,904 降到 8,912,896 字节，后续次数持平，因为旧版已在同一标题生命周期内保留资源；TH08 每次从 3,457,024 降到 3,325,952 字节。不能把这一项的减少等同于帧率按同比例提高；软件 GPU 与同时运行的测试也不适合拿绝对耗时作手机性能结论。

最终浏览器交互、音频、离线存档、录像和源码恢复记录以发行包 `validation/summary.json` 及对应文件为准，报告绑定实际 Wasm 哈希。桌面手机尺寸与 CPU 降速测试不是实体手机测试，有限轨迹也不能证明所有输入组合都等价。单次资源创建仍可能超过分步加载预算，不能承诺任意手机绝不掉帧。

构建：`node portable/build.mjs --th10`，随后 `node portable/package-architecture.mjs`。正式包在 `th10_web/artifacts/sdl-release`，公网服务仍使用其中的 `site`，端口 8090。构建依赖与资源恢复步骤沿用 `ARCHITECTURE-3.0.md`。
