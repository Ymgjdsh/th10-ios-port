# 永夜抄 3.4 / 风神录 3.5：六项性能优化

两款使用 SDL3、C++ 游戏管理器与 WebGL2 后端。此次参考本地红魔乡、妖妖梦的 CPU 顶点生成、批次上传和固定顶点布局做法，保留各自游戏的逻辑、透明绘制顺序、数值取整和资源生命周期。

## 已实现

| 项目 | 实现与边界 |
| --- | --- |
| 精灵计算 | 常见有界坐标在原版单精度、最近偶数取整模式下直接执行 C++ float 运算，保留每一步运算顺序。其他精度、特殊数值、极端缩放使用原来的 Extended 实现。没有更改弹幕、碰撞或随机数规则。 |
| 顶点复制 | 两款游戏已经合并的三角形批次直接上传；渲染器立即消费游戏缓冲，不保存即将被覆盖的指针。零散几何仍按原顺序合并，风神录的模型实例批次继续保留。 |
| GL 状态 | 缓存 VAO、纹理和读写帧缓冲绑定。固定布局只设置一次；截图、清屏、释放纹理、重建上下文后正确恢复状态。网页继续每批 glBufferData，起始偏移为零。 |
| 资源与着色器 | 启动时预编译常见组合；其他组合使用已链接的通用程序，绘制期间不再同步编译。永夜抄增加共通资源、第一和第二面、四组自机与 staff 动画的预加载，缓存上限 32 MiB；风神录增加 bullet、front、两名自机资源，缓存上限 32 MiB，并保留场景加载时的分步准备。缓存空间不足时正常加载，避免无限增加手机内存占用。 |
| 截图缩放 | 永夜抄暂停截图的原版三角滤波在 GPU 执行，保留原权重、源像素累加顺序和向零取整。用整数运算复现关键单精度运算，避免驱动融合乘加与近似倒数带来的差异。启动时检查实际 GPU 的 18 组格式转换；校验失败或不支持的模式仍使用原算法。校验后，正常暂停不再读回 GPU 像素。风神录原有 GPU 拷贝继续保留。 |
| 节奏与音频 | 固定 60 Hz 更新，短暂迟到后最多补四次逻辑和原版绘制，一次显示回调只呈现最后一帧；最多保留 100ms 欠账，暂停时清空。音频一次回调可补多块到既有水位，不再被单块补充速度限制。停止后遗留的回调不能启动第二条循环。 |

## 验证与测量

在桌面 Intel UHD 730 / Chromium WebGL2、390×844 手机视口下，以相同录像或输入进行 A/B 测量。耗时为 C++ 更新与提交调用的墙钟时间，不是手机 GPU 完成时间，也不是对实体手机帧率的承诺。

| 测量 | 永夜抄，Extra 10,000 帧 | 风神录，一面 14,000 帧 |
| --- | ---: | ---: |
| 优化前单帧中位数 | 0.9ms | 0.5ms |
| 优化后单帧中位数 | 0.8ms | 0.4ms |
| 优化前 P95 | 2.2ms | 1.4ms |
| 优化后 P95 | 1.7ms | 1.1ms |
| 优化前顶点属性设置 | 786,395 | 1,707,310 |
| 优化后顶点属性设置 | 2 | 0 |

A/B 抽样游戏状态与画面完全一致。风神录直接上传使绘制次数增加约 0.26%，同时减少顶点复制与提交耗时；永夜抄绘制次数不变。没有通过少画弹幕、减少特效、降低逻辑更新率或修改碰撞规则换取这些结果。

另外验证了原版顶点、旋转、投影、混合与提交顺序；2,040 万项数值检查；暂停变暗、模糊和恢复的逐像素结果；显示回调为 60/30/15 Hz 时的固定更新与音频补充；Music Room 三轮进入与返回；网页更新后资源复用、录像保留。完整录像、触控、录像保存和最终发布信息见发行目录的 `validation` 报告。

复现入口：`portable/check-six-optimizations.mjs`、`check-capture-scenes.mjs`、`check-capture-driver.mjs`、`check-low-cadence.mjs`、`check-frame-cadence.mjs`。原版对照与录像测试仍在各游戏开发目录中。

本地参考：`th10_web/reference/eagler-th06`、`th10_web/reference/eagler-th07`。没有以参考仓库内的风神录作为新的实现来源。

## 仍需实体手机验证的范围

WebGL 驱动、设备温度、浏览器后台调度、GPU 填充速度和不同弹幕场景仍会影响实际帧率。这里的优化与自动对照不能证明所有设备始终 60fps。特殊数值的精度兼容路径、GPU 滤波失败后的 CPU 回退、超出预加载预算的资源路径都是有意保留的正确性保障。
